# Connect v0.9.1 USB Gamepad Implementation Plan

> Approved and implemented on 2026-11-03, inline with focused tests. Final validation is in `gamepad-progress.md`; the user will perform Linux/controller testing on their separate Linux machine.

**Goal:** Correct Linux USB button layouts and add controller detection, live testing, and saved button/trigger remapping, with Windows and Linux v0.9.1 builds.

**Architecture:** One App-owned gilrs worker serves local Settings and forwards input directly to the current session. Automatic mapping stays intact; custom profiles bind native input sources to existing Xbox report destinations. Reuse the current protocol, permission checks, ViGEm host, and serde/RON storage.

**Tech Stack:** Rust 2024 workspace, gilrs 0.11.2, eframe/egui 0.37, serde/RON, existing QUIC input transport and ViGEm host.

**Spec:** [Proposed design](../specs/2026-11-03-gamepad-v0.9.1-design.md).

## Global constraints

- USB controller support only; no Bluetooth work, Linux hosting, codec, transport, or video-performance changes.
- Windows host/viewer and Linux viewer; retain four forwarded gamepads.
- Keep `PROTOCOL_VERSION = 8` and the current serialized input types unchanged.
- Reuse locked dependencies. Do not globally swap Linux A/X or shoulders/triggers.
- Preserve host permissions, input ordering, quick button edges, and release on focus/permission/session/device changes.
- Package `connect.exe`, `connect-linux-x86_64`, and updater-compatible `SHA256SUMS.txt` for version 0.9.1.

## Review focus

- Held controls, repeats, drift, and other controllers must not complete a rebind (Task 3).
- Axis-backed D-pads and independently varying analog LT/RT must preserve their actual meaning (Tasks 1–2).
- Profile identity must survive reconnect without leaking Linux codes into Windows or mixing live devices (Tasks 2–3).
- Invalid profiles must not reset unrelated settings, and staged edits must not be saved accidentally (Tasks 2–3).
- Permission/focus loss, hotplug, and a replacement session must not leave stuck or cross-session input (Task 3).

## Task 1: Pin down the mismatched layout and lock regression cases

- [ ] Record controller OS name, UUID, optional VID/PID, distribution/kernel, USB mode, backend-reported input code/type/value and logical label for each control. Use a temporary development diagnostic in the existing reader if needed; never log unrelated keyboard input.
- [ ] Follow physical A and LB through capture, generated `GamepadState`, protocol round trip and host `XGamepad`. Determine the first stage that changes their meaning. Check whether Steam Input or a virtual-controller layer is presenting another device; do not change the user's system configuration as a workaround.
- [ ] Add table-driven fixtures in `gamepad/mapping.rs`: a source currently labelled West must bind to A and release back to neutral; a source labelled LeftTrigger2 must bind to LB without also setting LT. Use synthetic source codes for unit tests and add the observed controller fixture when available.
- [ ] Include all face buttons, shoulders, Start/Back/Guide, stick clicks, D-pad buttons/axis directions, LT/RT at rest/half/full pull, diagonal input, and simultaneous buttons. Assert neutral/release as well as pressed output. Preserve existing stick orientation and range.
- [ ] Run the new mapping tests and confirm the reported mapping cases fail before implementing their correction. If gilrs cannot expose a required input, document that specific limitation and revisit the backend choice rather than masking it with a global swap.

**Deliverable:** Identified failure stage plus hardware-independent failing regression fixtures; hardware reproduction remains explicitly pending if that device is unavailable.

## Task 2: Implement profiles and deterministic report mapping

**Interfaces in `gamepad/mapping.rs`:**

- `ControllerKey`: platform, controller UUID and optional VID/PID, with OS-name fallback. Live instance ID and forwarding slot are separate runtime values.
- `Source`: gilrs native code as `u32`, button/value or signed-axis direction/range. Native codes are compared to observed `Code::into_u32()` values, never reconstructed with unsafe code.
- `Target`: each existing Xbox digital button and LT/RT. Keep ordinary stick axes on their existing automatic path.
- `ControllerProfile`: versioned model key, explicit target bindings seeded from automatic bindings, and validation errors local to that record.
- `map_state(profile: &ControllerProfile, input: &SourceSnapshot, automatic: GamepadState) -> GamepadState`: pure conversion used by both preview and forwarding; an explicit unbind suppresses the automatic target.

- [ ] Write tests for profile serialization, v0.9.0 settings migration, a bad profile alongside valid settings, platform separation, missing/zero identity fallback, shared model profiles across replug, explicit unbind, and reset to automatic.
- [ ] Implement native-code-aware button/value snapshots using the existing gilrs event/state APIs, including `Unknown` labels. Keep press state and analog value distinct. Retain the existing filters and single state-update behavior.
- [ ] Implement mapping once: one source/direction per destination assignment, conflict validation, exact Xbox bit/range output, clamping, and neutral output for unavailable sources. Axis-to-button uses fixed hysteresis (press 0.75, release 0.65 of its calibrated active range); analog trigger mapping is linear from observed released to full pull. Reject non-finite or zero-span calibration. Digital-to-trigger produces only 0 or 255.
- [ ] Ensure a custom binding replaces the previous default route: rebinding physical A to A cannot additionally emit X; rebinding LB cannot additionally emit LT. Support shared-axis halves for D-pads/triggers without treating opposite directions as duplicate sources.
- [ ] Add defaulted `gamepad_profiles` to Settings, isolate profile decoding/validation failures, and keep all unsaved editor state outside Settings. Valid older files retain their account, computers, trust and viewing settings.
- [ ] Run `cargo test --locked -p connect --bin connect gui::gamepad::mapping::tests` and `cargo test --locked -p connect --bin connect gui::settings::tests`; expect all new regressions and existing settings tests to pass.

**Deliverable:** Tested profiles and pure report generation, with no protocol or dependency change.

## Task 3: Connect discovery, Settings, and safe forwarding

**Worker interface in `gamepad.rs`:** `ControllerManager::start`, `snapshot`, `attach(ClientHandle)`, `set_active(bool)`, `detach`, and profile updates; implement a single owning worker rather than one reader per consumer. Keep rebinding capture restricted to the selected live controller. Settings edits are local and apply while disconnected.

- [ ] Add worker/lifecycle tests with a small in-memory event seam, not a new backend abstraction: quick down/up yields two ordered reports; unplug while held yields removal; focus loss/revocation yields neutral; focus regain republishes current state; old session cannot receive events after detach; four stable slots and a fifth non-forwarded controller; device disconnect during rebind cancels capture.
- [ ] Move reader ownership to App. Keep event-driven direct forwarding and latest-state UI snapshots separate. Service control changes at least every 20 ms, publish GUI wakeups only while the local tester is visible, and stop/join the worker during shutdown. Do not let a UI lock span input forwarding.
- [ ] Add the Gamepads card on Linux and Windows. Expose discovery, selector, live Xbox preview, optional source diagnostics, backend error messages, profile status and non-forwarded device status. Reuse existing widgets and accessible text labels; do not rely on color alone.
- [ ] Add rebind capture tests: ignore existing held buttons and repeats; wait for neutral then a new press; reject ambiguous simultaneous input; ignore another controller and idle stick drift; cancel without saving; detect conflicts; apply once; restore automatic defaults. The tester calls the same mapping function as the sender.
- [ ] Wire session acceptance, permissions, focus, ending/replacement and App shutdown to the single manager. Keep Settings hidden during viewing as today. No testing/rebinding reports may reach a host.
- [ ] Extend `handshake.rs` using its existing `InputSink::Channel`: corrected A/LB reports arrive unchanged; quick edges stay ordered; revoking gamepad permission while held neutralizes that pad; refused input remains refused; closing the session releases state.
- [ ] Run the mapping/Settings tests, worker/capture tests, and `cargo test --locked -p connect-host --test handshake`. All must pass before release work.

**Deliverable:** Usable local detection/remapping and safe USB forwarding through existing sessions.

## Task 4: Validate both platforms and prepare v0.9.1

- [ ] On a Linux build machine with the existing Ubuntu 24.04/glibc 2.39 baseline, install only missing build prerequisites with authorization as needed: ALSA/udev development packages, pkg-config, NASM and the documented MinGW toolchain for Windows cross-builds. Native Windows MSVC is also supported by the repository; use the actual available environment without silently replacing release targets.
- [ ] Run focused checks above, then `cargo fmt --all -- --check` and `cargo test --locked --workspace`. Run lint checks supported by the repository/toolchain and triage pre-existing findings separately. Do not claim Linux behavior from Windows-only compilation.
- [ ] Perform the design's physical acceptance matrix: failing USB controller Linux → Windows first; Windows USB viewer → Windows host; at least one additional controller family where available; all buttons/axes, reconnect, saved mapping, fast taps, focus, permission changes, two/four pads, fifth-pad status, and one actual game. Missing hardware evidence blocks a claim that the reported hardware bug is fixed.
- [ ] Compare before/after on the same session and hardware with existing input CSV traces. Require preserved edges, no growing worker queue, no UI-frame dependency and no material p95/p99 regression; record the results without inventing a latency target or a Parsec win.
- [ ] Bump workspace version to `0.9.1` and regenerate only affected workspace entries in `Cargo.lock`. Update README with USB-only feature scope, remapping instructions, Linux input-access troubleshooting and unchanged Linux-viewer/Windows-host roles. Do not recommend running the GUI as root or broad input-device permissions.
- [ ] Build `cargo build --locked --release -p connect` for Linux and `cargo build --locked --release --target x86_64-pc-windows-gnu -p connect` for Windows (or native Windows MSVC when chosen explicitly). Verify both launch, report 0.9.1, and retain protocol 8.
- [ ] Test v0.9.1/v0.9.0 peers both ways, Linux shared-library requirements, artifact names and updater checksum parsing. Stage `connect.exe`, `connect-linux-x86_64`, `SHA256SUMS.txt` and release notes; publishing is a later explicit action.

**Deliverable:** Reviewable v0.9.1 release artifacts and an honest test report for both platforms.
